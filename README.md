# 被紀念的痕跡 — 手部辨識 v3

## 使用

- 按「開始鏡頭體驗」。首次需連線下載手部模型，載入期間會顯示提示及鏡頭预覽。
- 將一隻手掌朝向鏡頭、自然張開五指。綠色骨架代表姿勢適合；黄色及文字提示表示需調整。
- 穩定停留三秒 → 淡痕 → 移開 → 再次輕觸 → 清晰顯影。輕微抖動經過平滑處理，短暫失去追蹤會暫停進度，超過 900ms 才重設。
- 不再用亮度分割辨認手掌，也不要求深色背景。仍應避免過暗、強逆光、遮擋及極端側面。
- 「停止鏡頭」、切換示範或離開頁面會關閉鏡頭及辨識程序。
- `?demo=1` 直接看示範，`?debug=1` 顯示流程狀態；右上角應顯示 v3。

## 算法與隱私

`hand-worker.js` 在 Web Worker 內使用固定版本 MediaPipe Tasks Vision **1.0.1** 與 Hand Landmarker float16 v1 模型。模型最多偵測兩隻手以提示「一次一隻」。CPU 推論不阻塞石膏動畫主執行緒；每次最多一個待處理影格，僅在有新視訊畫面時送出。

依賴從 jsDelivr 下載，模型從 Google Storage 下載。影像只在本機頁面／worker 記憶體處理，程式不把相機影像、關鍵點或掌印上傳或持久儲存。第三方仍會收到一般資源下載請求；首次辨識需要網絡，未保證離線辨識。

`hand-shape.mjs` 以 21 個關鍵點生成近似手形，保持比例並旋正。這不是逐像素分割、真實深度、壓力量測或真實掌紋掃描；掌紋仍是藝術化模板，手指粗幼亦是估算。姿勢檢查不是可靠的掌面／手背分類器，請依指示以掌心朝鏡頭。

`capture-landmarks.mjs` 管理相機、鏡像骨架、模型載入及錯誤清理；`interaction.mjs` 管理停留／寬限時間及原有敘事。`app.mjs` 保留 v2 的真正凹陷石膏渲染。

舊 `capture.mjs` 只保留作歷史算法比較，不會被新版載入；模型失敗不會偷偷退回亮度分割。

## 驗證

`node --test tests/*.test.mjs`：九項測試（五項原有、四項關鍵點／時序／左右手／手形測試）。2026-09-17 全部通過。

另以 Edge 無介面瀏覽器驗證：真實模型載入與空白影格、MediaPipe 官方 `right_hands.jpg` 中裁出的單手（淺色背景），完整三秒停留／移開／再接觸／顯影、桌面／手機、鏡頭拒絕與恢復、模型載入失敗，以及資源關閉。沒有使用使用者實體鏡頭；現場光線、不同膚色及雜亂背景仍待現場驗收。
